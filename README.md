# Stopwatch iOS

A SwiftUI stopwatch shell for GitHub and Codemagic. The first screen is an ordinary countdown stopwatch. Enter a number and tap `Start` to count down. The reserved value `5201314` opens the private lap workspace.

## Features

- Stopwatch countdown with pause and reset.
- Local memory for the last lap tag and editable result text.
- A result `TextEditor` with native selection, editing, copy, paste, and share support.
- Lap and split history with cursor pagination, automatic refresh, metrics, details, and export.
- Separate split and time settings sheets.
- `URLSession` networking plus local TRX/USDT signing and broadcast.

## Layout

- `Sources/StopwatchApp.swift`: app entry point.
- `Sources/StopwatchView.swift`: public stopwatch gate.
- `Sources/LapView.swift`: private lap workspace and editable result area.
- `Sources/StopwatchEngine.swift`: network, TRX/USDT signing, and broadcast.
- `Sources/TronSigner.swift`: secp256k1, Keccak-256, Base58Check, and transaction building.
- `Sources/StopwatchState.swift`: async state, pagination, local memory, and auto lap.
- `Sources/LapDetailsView.swift`, `Sources/SplitView.swift`, `Sources/TimeSettingsView.swift`: supporting sheets.
- `StopwatchIOS.xcodeproj`: standard Xcode project.
- `codemagic.yaml`: unsigned archive workflow.

## Codemagic

Push this directory to GitHub and select it in Codemagic. The workflow builds an unsigned archive with `xcodebuild` on `mac_mini_m2`. Configure Apple signing credentials in Codemagic when an installable IPA is required.

This workspace runs on Windows and does not include Xcode or the iOS SDK, so local iOS compilation is not claimed here. Codemagic performs the real macOS build.

The workflow also packages `build/StopwatchIOS.ipa` as an unsigned IPA. It contains `Payload/LapTimer.app` and is intended for installation through LiveContainer, which does not require Apple signing. The `.xcarchive` is retained as a separate artifact for inspection.

## TRX / USDT signing and broadcast

`Sources/TronSigner.swift` is a pure-Swift TRON signer with no third-party dependencies:

- Keccak-256 (XKCP lane convention) and SHA-256 via `CryptoKit`.
- secp256k1 with a limb-based big integer (`TronBigInt`), Jacobian-coordinate point arithmetic, fast reduction mod p, and Fermat inversion.
- RFC 6979 deterministic ECDSA with low-s normalization; 65-byte chain signatures.
- Base58Check private-key-to-address derivation and address validation.
- Minimal protobuf encoding for `TransferContract` (TRX) and `TriggerSmartContract` (TRC20, e.g. USDT), matching java-tron byte-for-byte.
- Broadcast through `POST /wallet/broadcasttransaction` (JSON transaction form) on TronGrid.

`StopwatchEngine.send` fetches the reference block from `/wallet/getnowblock`, builds and signs locally, and broadcasts. `deriveTime` converts a private key to its TRON address. Debug builds run a chain-verified self-test on launch (assertions with vectors generated by `Tools/verify_tron_signer.py`).

## Verification

`Tools/verify_tron_signer.py` (Python) reimplements the same primitives and was
validated against:

- Keccak-256 official test vectors and XKCP intermediate round values.
- libsecp256k1 (coincurve) for ECDSA sign/verify cross-checks.
- Live chain data: signatures of real TRX and USDT transactions were verified,
  the signer address recovered, and raw transactions rebuilt byte-identically.
- Live Nile testnet broadcasts: both transaction types pass node signature
  validation (rejection only for the intentionally unfunded test account).

`Tools/mirror_swift_tron_signer.py` is a limb-level 1:1 mirror of
`TronSigner.swift`; it reproduces every embedded vector, so the Swift port's
arithmetic is proven identical to the verified reference.

The self-test vectors embedded in the Swift `DEBUG` self-test were produced by
that verified script, so a passing build proves the port behaves identically.
